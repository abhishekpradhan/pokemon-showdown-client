# Support

Search [existing issues](https://github.com/abhishekpradhan/pokemon-showdown-client/issues) before opening a new one. Use the bug or protocol form and include the build revision (Settings → About, or `/build-info.json`), your browser, the server you were connected to, reproduction steps, and a share-safe diagnostic export from Settings that you have reviewed. The feature form asks what workflow is missing and how the official client handles it.

For setup problems, include the failing command and the sanitised error rather than an environment file. [docs/self-hosting.md](docs/self-hosting.md) and [docs/offline.md](docs/offline.md) cover the common deployment and browser-storage problems. Game mechanics, server moderation and official-account issues belong with the Pokémon Showdown community or the server you use.

## Maintenance

[@abhishekpradhan](https://github.com/abhishekpradhan) maintains the project and aims to triage new actionable issues weekly; this is a volunteer project, so response and review times vary. Issues are labelled `bug`, `compatibility`, `enhancement`, `documentation`, `good first issue` and `help wanted`. Agree the scope of a large change in its issue before implementing it.

Security reports and any other confidential matter go through the private channel in [SECURITY.md](SECURITY.md). Use GitHub's own reporting tools for abuse on GitHub.

If maintenance ever changes hands, the successor, release and deployment access, the private reporting channel and the handling of existing confidential reports will be documented first. Anyone may maintain an attributed fork under the project license if the project becomes inactive.
