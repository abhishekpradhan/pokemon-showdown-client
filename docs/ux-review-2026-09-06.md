# UX review and polish — 1.1.1

Reviewed the 1.1.0 release (`6cce11bd`) through desktop and mobile browser interactions, screenshots, keyboard navigation, and the existing accessibility checks. The objective was a calmer working interface with clearer next actions, compact secondary controls, and predictable focus, dismissal and loading behavior. Existing dialog transitions, hover feedback and reduced-motion behavior support those interactions.

## Findings and changes

| Area | Observed friction | Change |
| --- | --- | --- |
| First battle | A disabled battle button required finding a separate name button further down the page. | The primary action resolves connection, name or team setup before offering Find battle. Naming does not implicitly start matchmaking. |
| Format and team | Server-provided formats still presented a saved-team selector. | Provided teams have a clear informational field; matchmaking lists searchable supported formats. |
| Home | Repeated blocked-state warnings, decorative chrome and stretched empty panels competed with setup. | Compact setup status, shorter copy, a direct Random Battle shortcut and content-sized panels. |
| Mobile navigation | Theme buttons took space while the current context and player name disappeared. | A compact search action, visible page/conversation context and player label; theme remains in Settings. |
| Route orientation | Chat rooms and the battle directory displayed matchmaking context and incorrect primary selection. | Route-aware labels and active navigation for conversations and spectating. |
| Account | Opening did not focus the name field or reliably return to its opener. A failed rename could close an already-named user's dialog. | Explicit focus restoration, guest-first hierarchy, cancellation, and close only after successful confirmation. |
| Notifications | The custom panel lacked normal outside-click and Escape dismissal. | A named dialog with dismissal and trigger focus restoration. |
| Search | Keyboard selection was not announced, dismissed filters could persist, punctuation matched every normalized label, and choosing a different team did not update an already-open editor. | Combobox semantics, active-result announcement, explicit close, fresh queries, addressed team navigation and focus continuity. |
| Modal layers | Mobile navigation could draw over dialogs and battle controls. | Consistent overlay/content layers above app navigation, including nested confirmation dialogs. |
| Selectors | Challenge selectors portaled outside the modal focus boundary and could not receive focus or clicks. | Keep modal selectors in their focus scope while escaping clipping; dismiss the selector before its enclosing dialog. |
| Small viewports | Selectors used the layout viewport and could overflow or remain awkward when focus changed. | Visible-viewport positioning, bounded popups, fresh filters and predictable keyboard exit. |
| Session tabs | Newly active tabs could be offscreen and closing background tabs could drop focus. | Reveal active tabs, restore a useful focus target and expose close controls on touch. |
| Team library | The entire library preceded editing on mobile. | A mobile library disclosure retains a visible page heading and direct New team action. |
| Team editor | Controls overflowed the viewport; adding a Pokémon placed its editor below the visible roster. | Responsive toolbar, compact roster navigation, focused species entry and reachable save actions; delayed data never interrupts another focused field. |
| Set details | Repeated suggestions and all advanced fields overwhelmed initial editing. | Clearer field groups and progressive detail while preserving every supported set field. |
| Removing Pokémon | An accidental removal interrupted editing. | A visible undo action preserves the removed set and editing context. |
| Offline editing | A generic red WebSocket error made the usable local editor look broken. | Explain the unavailable live connection in an informational message, retain actual save/import errors, and remove stale connection warnings after reconnection. |
| Spectating | The flexible grid assigned a large battlefield-sized row to playback controls. | Compact playback sizing gives space back to the field. |
| Battle decisions | Choosing a move dropped focus; targets were narrow and backing out depended on obscure icons. | Focus the next decision, provide readable target choices, Back to moves and Change choice. |
| Mobile battle details | The inspector did not behave as a modal and Escape did not close it. | Accessible sheet, keyboard tabs, Escape dismissal and focus restoration. |
| Mobile moves and bench | Tall controls and icon-only team slots obscured useful information. | Compact two-column moves, readable team labels/HP and reachable timer/actions. |
| Room directory | Favorites doubled each row's height; pasted invalid joins silently failed. | Compact favorite controls, wrapped search/join controls and actionable validation. |
| Conversation tools | Roster/history filters shared state and leaked across conversations. | Independent filters with room-local reset behavior and truthful empty states. |
| Chat drafts | Multiline text clipped; Tab completion ignored the caret; stale errors persisted while editing. | Auto-growing drafts, caret-aware completion, focus recovery and refreshed error feedback. |
| Spoilers | Touch/keyboard reveal was unreliable and live announcements could disclose hidden text. | Explicit accessible reveal controls and spoiler-safe announcements. |
| Replay entry | An empty player and disabled controls pushed loading below the first mobile viewport. | A compact empty state with immediate loading controls; playback appears after loading and receives focus unless the user has moved on to another interaction. |
| Replay search | Old results and pagination remained after changing filters. | Reset stale results/page state and cancel superseded searches. |
| Settings | Unstyled preference inputs and a long page made controls difficult to find. | Consistent fields, responsive controls and section links that scroll and focus the destination. |

## Verification

Focused browser regressions cover the corrected workflows in `ux-shell`, `ux-teams`, `ux-select`, `ux-battle` and `ux-community`. The release also runs the existing Chromium/mobile/Firefox/WebKit workflows, axe checks, reviewed visual baselines, TypeScript/ESLint, unit tests, production/offline checks, controlled-server integration and dependency/license/bundle gates. Exact committed CI and hosted verification results are recorded in the [1.1.1 release](https://github.com/abhishekpradhan/pokemon-showdown-client/releases/tag/v1.1.1).

The review used isolated browser contexts and controlled simulator fixtures. It is not a physical-device or complete screen-reader certification. Team storage and protocol support retain the documented [compatibility contract](compatibility.md).
